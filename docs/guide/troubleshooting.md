# Troubleshooting

Common issues, diagnostics, and solutions when working with React Native Neutralinojs.

---

## 1. Invalid Hook Call / React DOM Mismatch

### Symptom:

Console error: `Error: Invalid hook call. Hooks can only be called inside the body of a function component` or `Cannot read properties of null (reading 'useMemo')`.

### Cause:

The installed version of `react-dom` differs from your project's `react` version. React requires `react` and `react-dom` to have identical minor and patch versions.

### Solution:

Check your `package.json` and reinstall `react-dom` with the exact version flag:

```bash
# If your react is version 18.3.1:
pnpm add react-dom@18.3.1 --save-exact
```

---

## 2. Port Collision (`port 8082 already in use`)

### Symptom:

Vite dev server fails to bind or connects to unexpected port.

### Solution:

Specify a custom port in `neutralino/vite.config.ts`:

```typescript
import { defineConfig } from 'vite';

export default defineConfig({
  server: {
    port: 8090, // Change to any available port
  },
});
```

---

## 3. Neutralino Binary Execution Error on Linux

### Symptom:

`neu.err.log` shows error loading shared libraries: `libwebkit2gtk-4.1.so.0: cannot open shared object file: No such file or directory`.

### Solution:

Install WebKitGTK using your Linux distribution package manager:

::: code-group

```bash [Ubuntu / Debian]
sudo apt-get update && sudo apt-get install -y libwebkit2gtk-4.1-0
```

```bash [Arch Linux]
sudo pacman -S webkit2gtk-4.1
```

```bash [Fedora]
sudo dnf install webkit2gtk4.1
```

:::

## 4. Diagnosing with React Native Doctor

If you are unsure whether your project setup is complete, run the CLI healthchecks:

```bash
npx react-native doctor
```

The doctor tool will automatically verify:

- Whether `neutralino.config.json` is properly initialized.
- Whether the required Neutralino binaries are downloaded in `neutralino/bin/`.
- Offer automatic remediation by pressing the fix key in the interactive prompt.

---

## 5. Inspecting Debug Logs

All stdout, stderr, and Neutralino CLI logs are persisted in the `neutralino/log/` folder:

| Log File                     | Description                                                   |
| :--------------------------- | :------------------------------------------------------------ |
| `neutralino/log/neu.log`     | Standard output stream of the Neutralino desktop process.     |
| `neutralino/log/neu.err.log` | Error output and runtime warnings from the Neutralino binary. |
| `neutralino/log/cli.log`     | Logs generated by `npx neu update` or `npx neu build`.        |
| `neutralino/log/cli.err.log` | Errors encountered during CLI operations.                     |
